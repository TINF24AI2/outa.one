# Gruppenreflexion

### Was hat insgesamt gut funktioniert:

- Umsetzen der Issues -> Fertigwerden der Sprintziele
- Langfristiger Blick auf das Projekt -> trotzdem Fokus auf einzelne Sprints und Agilität
- Kommunikation unter den Devs -> Pair Programming, PR-Reviews, Dokumentation
  - Hilfestellung von erfahreneren Teammitgliedern

### Herausforderungen -> Umsetzung der Retrospektiven

| Thema                           | Beobachtung                                                                                               | Maßnahme / Lernen                                                        |
| ------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Sprint 0                        | Alle hatten schon Erfahrung mit agilen Methoden (Praxis) -> die Erfahrungen haben sich aber unterschieden | Alle zuerst auf einen gemeinsamen Nenner bringen: Was wollen wir machen? |
| Überblick (Dev - Product Owner) | Kein Überblick zwischen Devs und Product Owner                                                            | Weekly und genauere PR-Beschreibung                                      |
| Zeitplanung                     | Erster Sprint war relativ knapp vor Schluss                                                               | Spätere Sprints hatten dann mehr Puffer                                  |
| Issue-Abhängigkeiten            | Issue-Abhängigkeiten können zu Problemen führen                                                           | Entweder keine Abhängigkeiten oder frühzeitig kommunizieren / entfernen  |

### Welche Fehler haben wir gemacht und was lernen wir daraus?

**Review**

- Statt dass jeder seine Issues vorstellt: Review mehr als Kundenpräsentation -> eine Art Abschlussbericht für jeden Sprint

**Sprint-Übergang**

- Mehr toolgestütztes Arbeiten: GitHub Projects, Miro, Planning Poker

**User Stories**

- Der Sinn hinter Akzeptanzkriterien: Klarheit über die Anforderungen schaffen -> Umsetzung erfolgen zielgerichtet
